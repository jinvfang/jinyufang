2.5 DoF Carnival Fishing

Electromechanical DesignerElectromechanical Design, Boston University · Group 7 team projectSep 2026 — Oct 2026

Project overview

A Joystick-Controlled Carnival Fishing Game.

Our team built a 2.5-degree-of-freedom gantry that turns the carnival fishing game into a machine: the player steers an electromagnet over a spinning plate of fish with a joystick, dips it to pick a fish up, and drops it in the bucket.

The gantry moves freely in X and Y, which gives two full degrees of freedom. The third axis, Z, only has two positions, up and down: one press of the joystick lowers the magnet, pauses, and lifts it back up. That limited vertical motion is the “half” degree of freedom. A fifth stepper motor spins the plate underneath to make the game harder, and everything runs from one handheld joystick and one control board.

This page follows the project in order: the brief, how it plays, the first linear stage, the CAD models, each part as built, manufacturing, electronics and code, and the final assembly.

Key Work & Outcomes

  • Demonstrated the working game to our professor, who played it with the joystick.
  • Built a belt-driven gantry on 80/20 aluminum extrusion with X–Y travel of up to 50 mm/s and a 10 mm Z dip.
  • Designed a purpose-built end effector: a printed holder that carries an electromagnet, plus 3D-printed fish with steel screws for it to grab.
  • Drove five stepper motors (two for X, plus Y, Z, and the plate) and the electromagnet from one MKS Base board.
  • Wrote Arduino firmware over seven versions that maps one joystick to movement, the Z dip, the magnet, and a three-round game.
  • Modeled every printed part in SolidWorks, with equation-driven motor mounts sized from the NEMA 17 dimensions.

How it plays

One Joystick, Four Actions

The player lines the magnet up over a fish, switches the magnet on, dips to pick the fish up, and carries it to the bucket.

Pushing the stick further moves the gantry faster, so small corrections are easy and long moves are quick. While the magnet is dipping, X and Y are locked so the player can’t drag the magnet sideways through the fish.

Joystick inputWhat the machine does
Push the stickMoves the magnet in X and Y; speed follows how far the stick is pushed
Press onceZ dips down 10 mm, pauses for 0.3 s, and comes back up
Press twice quicklyTurns the electromagnet on or off
Hold for 0.8 sStarts the plate game, or stops it early

The plate game gets harder each round, with a 3-second pause between rounds:

RoundLengthPlate motion
Round 160 sOne turn every 4 s
Round 245 sTwice as fast (one turn every 2 s), in the opposite direction
Round 360 sSplit into 2–4 random parts; every part reverses direction at a new random speed

First linear stage

Starting With One Axis

Before designing the gantry, we built and tested a single linear stage.

The first stage used a NEMA 17 stepper turning a lead screw through a flexible coupler. A brass nut drove a foam-board carriage along the screw, with a pillow-block bearing supporting the far end. We drove it with G-code through Marlin firmware, configured at 400 steps/mm for the 8 mm-per-turn lead screw, then stacked two stages into the in-class plotter.

For the fishing game, we kept the NEMA 17 motors and the MKS Base board but switched to timing belts running on 80/20 aluminum extrusion. Belts move a carriage much faster than a lead screw, which a game needs, and the extrusion serves as both the frame and the rail.

CAD models

Designed In SolidWorks

The whole machine was modeled as one SolidWorks assembly, built up from subassemblies for each axis, the plate, and the controls.

We imported vendor models of the NEMA 17 motors, timing pulleys, MKS Base board, and joystick module to check fit and clearances. The motor mounts are driven by global equations (a 1.7 in motor face, 1.2205 in between mounting holes, a 5 mm shaft, and the 1 in extrusion size), so changing one number updates every mount.

Electronics & code

From Stick To Steps

One MKS Base board (an ATmega2560 running Arduino code) reads the joystick and drives five steppers and the magnet.

DeviceBoard connection
Joystick X / YAnalog pins A11 and A12
Joystick buttonPin D19, with the internal pull-up
X motors (two)X and E0 driver slots, stepped together; one is reversed in code because the two motors face opposite ways
Y and Z motorsY and Z driver slots
Plate motorE1 driver slot

We first planned to run the gantry on GRBL with G-code jog commands streamed from a laptop script that read the joystick. We switched to our own Arduino firmware so the joystick plugs straight into the board and no computer is needed during play. The firmware grew one feature at a time:

joystick_gantry_finalOct 20Round 3 with random parts, speeds, and direction changes

How the final firmware works:

  • Proportional speed. The stick is calibrated at power-on, ignores small movements near center (a dead zone), and scales speed up to 4,000 steps/s, which is 50 mm/s at 80 steps/mm.
  • Smooth acceleration. Speed ramps at 8,000 steps/s² so sudden stick moves don’t stall the motors.
  • Button decoding. Presses are counted on release, so the code can tell a single press, a double press, and a long hold apart.
  • Z dip state machine. Down, pause, up, then idle, with X and Y locked until the dip finishes.
  • Plate game. A timer steps through the rounds. Round 3’s parts and speeds are picked randomly each game, and the plate always slows to a stop before reversing.

The core of the joystick control:

// Stick reading -> signed target speed, with dead zone and proportional control
float stickToSpeed(int raw, int center) {
  int d = raw - center;
  if (abs(d) < DEADZONE) return 0;
  float span = (d > 0 ? 1023 - center : center) - DEADZONE;
  float f = (abs(d) - DEADZONE) / span;
  if (f > 1) f = 1;
  return (d > 0 ? f : -f) * MAX_SPEED_XY;
}

// Move current speed toward target, limited by acceleration
float ramp(float current, float target, float dt) {
  float maxDelta = ACCEL_XY * dt;
  if (target > current + maxDelta) return current + maxDelta;
  if (target < current - maxDelta) return current - maxDelta;
  return target;
}
